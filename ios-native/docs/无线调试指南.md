# iPhone 无线调试 / 安装指南

> 目标：让 iPhone 和这台 Windows 电脑连起来，**不用插线**就能装包、看日志、抓崩溃。
>
> ⚠️ 先说清楚一件事：**Windows 上没有 Xcode，所以不能「编译」iOS App**。
> 无线调试在 Windows 上能做的是：**安装（Sideloadly）+ 看实时日志 + 抓崩溃报告**。
> 编译仍然在 Codemagic 云端做。

---

## 一、先决条件

| 项目 | 要求 |
|---|---|
| Windows | 10 / 11（本机已满足） |
| iTunes | **必须是 Apple 官网版**，不是微软商店版 |
| 手机 | iPhone，**和电脑连同一个 Wi-Fi** |
| Apple ID | 免费账号即可（签名有效期 7 天） |

### 1.1 装 iTunes（关键：不能装商店版）

微软商店版 iTunes 删掉了 Apple Mobile Device Support，Sideloadly 找不到手机。

- 下载：<https://www.apple.com/itunes/download/win64>
- 装完确认服务在跑：

```powershell
Get-Service "Apple Mobile Device Service"
```

要看到 `Running`。如果没装这个服务，说明你装的是商店版，卸载重装官网版。

### 1.2 装 Sideloadly

- 下载：<https://sideloadly.io/>
- 装完**以管理员身份**运行（签名需要）

---

## 二、手机端设置（必须做全）

### 2.1 开启开发者模式（iOS 16+ 必需）

iOS 16 以后，即使用了免费证书，**不开发者模式就装不上**。

1. 设置 → 隐私与安全性 → 滑到底
2. 找到 **「开发者模式」** → 打开
3. **手机会重启**
4. 重启后回到锁屏，会弹「要打开开发者模式吗？」→ 确认

> 如果设置里**没有「开发者模式」这一项**：
> 先用 Sideloadly 尝试装一次（会失败），失败后这个选项才会出现。
> 这是 iOS 的机制，不是 bug。

### 2.2 信任证书

装完 App 后第一次打开会提示「不受信任的开发者」：

1. 设置 → 通用 → 关于本机 → 滑到底 → **证书信任设置**
2. 找到你的 Apple ID 邮箱 → 打开开关

### 2.3 记下你的 iPhone UDID 和局域网 IP

**UDID**（Sideloadly 会自动读，但记一下备用）：

```
方法：手机连上电脑 → Sideloadly 顶部会显示「Connected (Wi-Fi)」
```

**局域网 IP**：

```
设置 → 无线局域网 → 点当前 Wi-Fi 右边的 ⓘ
→ 看「IP 地址」那一行，例如 192.168.1.23
```

**手机名**（后面命令要用）：

```
设置 → 通用 → 关于本机 → 名称
```

## 三、开启无线调试（三种方式，按需选）

### 方式 A：Sideloadly 自带无线安装（**最简单，推荐**）

Sideloadly 从 0.30 版本开始支持 Wi-Fi 安装，不需要 iTunes 有线配对。

**步骤：**

1. 手机和电脑连**同一个 Wi-Fi**
2. 电脑上**以管理员身份**打开 Sideloadly
3. 手机**插一次数据线**，Sideloadly 识别到设备后，顶部设备下拉框右侧会出现 **Wi-Fi 图标**
4. 点那个 Wi-Fi 图标 → 选中你的手机 → **拔掉数据线**
5. 等一下，设备列表里手机会显示为 `你的手机名 (Wi-Fi)`
6. 把 `zstangshi-ios-unsigned.ipa` 拖进 Sideloadly
7. Apple ID 填你的邮箱
8. 点 **Start**

> 第一次必须插线配对一次，之后就可以完全无线。
> 如果 Wi-Fi 图标是灰的，说明 iTunes 版本不对或 Apple Mobile Device Service 没跑。

**验证无线是否真的生效：**

拔掉线后运行：

```powershell
# 需要先装 libimobiledevice（见下方方式 C）
idevice_id -l
ideviceinfo -k DeviceName
```

能列出设备名说明无线通了。

---

### 方式 B：iOS 17+ 的原生「无线调试」（给有 Mac 的场景）

iOS 17 起，iPhone 支持 **Remote Pairing**（`devicectl` 用的那套）。但：

> ❌ **Windows 上无法使用**，因为 `remotepairingd` 是 Xcode 的私有服务。
>
> 如果你有 Mac，做法是：
> 1. Mac 上 Xcode → Window → Devices and Simulators
> 2. 勾选 **Connect via network**
> 3. 之后同一 Wi-Fi 下自动无线连接

**这条路在本机走不通**，因为本机是 Windows。列在这里是为了说明：不要去找 `xcodebuild -destination 'platform=iOS,name=...'` 之类的命令，Windows 上没有。

---

### 方式 C：libimobiledevice 命令行（**看日志 / 抓崩溃用**）

这是 Windows 上**真正有用**的无线调试工具集。它能在无线状态下：装包、看实时系统日志、抓崩溃报告。

#### C.1 安装

**用 scoop（推荐）：**

```powershell
# 先装 scoop（如果还没装）
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
irm get.scoop.sh | iex

# 装 libimobiledevice 全家桶
scoop bucket add extras
scoop install libimobiledevice ideviceinstaller
```

**或者用 Chocolatey：**

```powershell
choco install imobiledevice -y
```

**或者手动下载**（不推荐，依赖多）：
<https://github.com/libimobiledevice-win32/imobiledevice-net/releases>

#### C.2 无线连接

libimobiledevice 的无线需要先 **usbmuxd 配对一次**，之后才能无线。

```powershell
# 1. 手机先插线，确认能识别
idevice_id -l

# 2. 建立配对记录
idevicepair pair

# 3. 开启无线同步（关键一步）
#    Windows 没有 usbmuxd 的 --wireless 参数，用 iTunes 的方式：
#    打开 iTunes → 设备 → 摘要 → 勾选「通过 Wi-Fi 与此 iPhone 同步」
#    （iTunes 12.9 之后这个选项在「选项」区域）

# 4. 拔线，等待 10 秒
# 5. 测试无线是否可用
idevice_id -l
```

**如果 `idevice_id -l` 无线状态下返回空**，说明 usbmuxd 没走网络。解决办法：

```powershell
# 用 Apple 的 usbmuxd，加一个网络监听
# 查看 Apple Mobile Device Service 对应的 usbmuxd
Get-Process | Where-Object { $_.Name -like "*AppleMobileDevice*" }

# 重启该服务
Restart-Service "Apple Mobile Device Service"
```

> Apple 的 usbmuxd 默认**只监听本地 TCP 27015**。无线设备会通过 Bonjour 广播，
> iTunes 能收到但 libimobiledevice 不一定能。**实践中最稳的是方式 A（Sideloadly）**。

#### C.3 常用命令

```powershell
# 列出已连接设备（含无线）
idevice_id -l

# 设备信息
ideviceinfo
ideviceinfo -k DeviceName
ideviceinfo -k ProductVersion
ideviceinfo -k ProductType

# 安装 ipa
ideviceinstaller -i zstangshi-ios-unsigned.ipa

# 卸载
ideviceinstaller -U com.tstc.zstangshi

# 列出已装应用
ideviceinstaller -l

# 实时系统日志（关键！看 App 报了什么错）
idevicesyslog | Select-String "ZhangShangTangShi"
```

**实时日志是本项目最重要的调试手段**——我们的网络层出错时会在日志里留痕。

## 四、看崩溃报告（App 闪退时）

### 4.1 手机端直接看

```
设置 → 隐私与安全性 → 分析与改进 → 分析数据
→ 找以 ZhangShangTangShi 开头的条目
```

### 4.2 用 libimobiledevice 导出

```powershell
idevicecrashreport -u (idevice_id -l) -k ./crashlogs
```

### 4.3 用 Sideloadly 看

Sideloadly 窗口底部有 **「Device logs」** 面板，闪退时会显示。

## 五、针对本项目的具体调试流程

### 5.1 装包

1. Codemagic 出包后下载 `zstangshi-ios-unsigned.ipa`
2. Sideloadly（无线）→ 拖入 → Apple ID → Start
3. 手机：设置 → 通用 → 关于本机 → 证书信任设置 → 信任

### 5.2 确认网络层是否真的通了

这是**上一版失败的核心**。装好后按这个顺序验证：

**第一步：看首页能不能显示**

- 能显示 = UI 层正常
- 白屏 = SwiftUI 布局崩了，去看崩溃报告

**第二步：点「我的」→ 登录**

- 看报错文案是什么：
  - 「连不上教务（超时）」→ 协议/网络问题
  - 「学号或密码不正确」→ 可能是误报
  - 「取加密公钥失败」→ 说明 HTTP 通了但解析失败

**第三步：开实时日志观察**

```powershell
# 装包前先开日志（保持运行）
idevicesyslog | Select-String -Pattern "ZhangShangTangShi|jwxt|chelaile|ATS|NSURLError"
```

关键要看有没有：

```
NSURLErrorDomain Code=-1022    → ATS 拦截了 http！
NSURLErrorDomain Code=-1001    → 超时（校外 https 不通）
NSURLErrorDomain Code=-1003    → DNS 失败
NSURLErrorDomain Code=-1004    → 连不上主机
```

> **-1022 是重点**：如果出现，说明 Info.plist 的 ATS 没生效。
> 本工程的 IPA 里 `NSAllowsArbitraryLoads=true`，正常不该出现。

### 5.3 教务协议验证（校外必看）

校外环境：**HTTPS 走不通，必须 HTTP**。本版已实现：

```
1. 首次请求时，HTTPS 和 HTTP **并发探测**（各 4 秒）
2. 谁先成功就用谁，并记住
3. 之后按记住的协议直连
4. 网络环境变了（记忆失效）→ 用 4 秒超时换协议重试
```

如果你在**校园网**里，HTTPS 能通，会自动走 HTTPS。

## 六、常见问题

| 现象 | 原因 | 解决 |
|---|---|---|
| Sideloadly 显示不了设备 | 装了商店版 iTunes | 卸载，装 apple.com 官网版 |
| Wi-Fi 图标是灰的 | 没插线配对过 / 服务没跑 | 插线配对一次；`Restart-Service "Apple Mobile Device Service"` |
| 装完打不开，提示不受信任 | 没信任证书 | 设置 → 通用 → 关于本机 → 证书信任设置 |
| 装完立刻闪退 | 没开发者模式 | 设置 → 隐私与安全性 → 开发者模式 |
| 7 天后又闪退 | 免费证书过期 | 重新用 Sideloadly 签一次（用同一 Apple ID） |
| `idevice_id -l` 无线返回空 | usbmuxd 没监听网络 | 用方式 A（Sideloadly）代替 |
| App 里所有网络都失败 | 手机用了代理/VPN | 关掉代理再试 |

## 八、当前版本已修的、与「不能用」直接相关的问题

| # | 问题 | 后果 | 修复 |
|---|---|---|---|
| 1 | `PageDeck` 里 4 个页面是**叠在一起**的（没有横向 HStack） | **点「课表」显示的是别的页** → 用户说的「底栏对应错误」 | 加 `HStack(spacing: 0)`，整条带真正横向排开 |
| 2 | 网络超时 20s + 换协议再 20s = **40 秒** | 校外 HTTPS 不通时等到超时，用户以为「登录一直失败」 | 主 10s、探测 4s（对齐安卓），并改成**并发探测双协议** |
| 3 | 课表图标用 `calendar`（带日期数字） | 和安卓的「表格」图标差异大 → 「页面和安卓不一样」 | 用安卓原始 pathData 绘制四个底栏图标 |
| 4 | SVG 解析器缺 `C/c` 贝塞尔 | 「我的」图标只有头、没肩膀 | 补上三次贝塞尔指令（35 项单测覆盖） |

> 第 1 条是**本轮最关键的发现**：它不是「样式不像」，而是**功能完全错位**。
